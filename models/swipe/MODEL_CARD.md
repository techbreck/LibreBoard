# LibreBoard Swipe Latin v1

## Status

No release weight file is accepted yet. This card describes the committed architecture and the
evidence that a candidate must acquire before `swipe-latin-v1.onnx` may enter the core APK.

## Design

The model is a 821,121-parameter, six-layer layout-conditioned Transformer CTC encoder. It consumes
64 normalized touch points and up to 64 live key centers. Its output classes identify positions in
that supplied key list, not hard-coded QWERTY letters. The pure-Kotlin decoder supplies the current
layout's labels, lexicon constraints, language lock, CTC blank/repeat handling, and geometric
fallback.

The trainable weights are licensed Apache-2.0. Training and export code remains part of the
GPL-3.0-only LibreBoard application source tree; the resulting data-only weights carry their own
license.

## Training data and exclusions

The only external gesture source approved for v1 is the MIT-licensed
[`futo-org/swipe.futo.org`](https://huggingface.co/datasets/futo-org/swipe.futo.org) dataset at commit
`d71bf5fd7f45b3e7c2ed2d76a21b0dbd3b4ba566`. Every required file size and SHA-256 is committed in
`models/sources/v1.json`. Sessions are re-split as indivisible units by a committed salted hash;
source partition names never override that split. The prepared corpus removes absolute timestamps,
hashes the already-anonymous session identifier, reports every rejected/duplicate row, and emits the
same 64-point tensor convention used on Android.

LibreBoard does **not** use FUTO application code, FUTO model weights, or outputs generated by FUTO
models. No Source First, proprietary, or non-commercial artifact is permitted in the training or
export path.

## Reproduction

On x86-64 Linux with Python 3.11:

```sh
uv venv --python 3.11 build/model-venv
uv pip install --python build/model-venv/bin/python \
  --require-hashes --torch-backend cpu \
  -r models/training/requirements-linux-x86_64.lock

python3 tools/model_sources.py fetch futo-swipe-dataset-v1 --accept-large-downloads
python3 tools/prepare_swipe_dataset.py
build/model-venv/bin/python tools/train_swipe_model.py --device cpu
build/model-venv/bin/python tools/export_swipe_model.py
```

The source fetch is intentionally explicit and is approximately 5.7 GB. A development smoke run
uses `--max-train-steps` and `--max-validation-steps`; its filenames contain `development` and it
cannot produce release-eligible evidence.

## Required acceptance evidence

A candidate is accepted only after its training/export reports, source/split hashes, ONNX operator
configuration, exact tensor ABI, file-size limit, Android p95 latency, added peak memory, and Phase 0
quality gates pass. The swipe gate is at least 90% top-1 and 95% top-3 overall, at least 90% top-3 on
short and return-trip strata, and at least 20% relative error reduction over the geometric decoder.
Measurements must include supported physical GrapheneOS Pixel hardware without sandboxed Google
Play. Until then, LibreBoard must keep using the geometric fallback when neural inference is absent,
late, or incompatible.

## Limitations

The approved external gesture corpus is English/QWERTY. The model's key-slot formulation permits
live layouts and the shared lexicon permits German candidates, but this does not establish German or
non-QWERTY quality. English/German, alternate-layout, short-word, repeated-letter, return-trip, and
high-deviation results must be reported separately before release.
